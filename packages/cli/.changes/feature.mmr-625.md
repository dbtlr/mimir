- **Launch a T3 Code thread from a task** (MMR-625). With T3 connected, a ready task's page shows **Launch on <system>** beside Start. One click creates a thread on that T3 system with the task's defaults: the T3 project's default model (else the last one used for this project in this browser), each option's default, the broadest runtime mode the connection allows, and the system's default workspace. The thread's first message is `Work <id>.`, and the task is queued with `harness=t3`, the thread as its session, and the system's environment id as its host. The caret menu launches on another linked system or opens **Choose settings…** for the model, effort, runtime mode, workspace, branch, and plan mode. A retry after a lost reply reaches the same thread, and a task another session has already queued is refused rather than launched twice. Tasks with a T3 thread show **Open in T3** on their Now row and task page; it opens the thread in the T3 app through its `t3code://` link.
- **Starting a queued task keeps its host and branch** (MMR-625). A plain `start` of a queued task no longer clears the host and branch its reservation recorded, so a task queued for a T3 thread keeps its Open in T3 link once the agent starts it. A start that leaves the task with a worker still clears them, and a host or branch the start supplies still replaces the stored one.
