- **An import refuses a hold reason on an open task with no hold** (MMR-621). A transfer document could give an open task `hold: none` with a `hold_reason`, and the task then read as unheld with a reason, a state no command writes. `mimir store import` now refuses that document with "node KEY-N.hold_reason must be null while the hold is none", as it already refused a `block_owner` on a task that is not blocked. A done or abandoned task with a leftover reason still imports, with the reason cleared. Earlier releases' import stored such a document as given, so a store that once imported one exports a document this release refuses: remove the `hold_reason` from that task in the document, or park and unpark the task before exporting.
