- **The skill describes mechanics, not delivery policy** (MMR-608). The `mimir` skill states what each record, status, and verb means and leaves when to read the board, which work to take, and how to route follow-ups to the user's and the project's own process. It no longer requires orienting before every request, preferring groomed work, holding one `in_progress` task per session, filing every deferred follow-up as a task, settling every task at session end, or writing all three finishing records in order. `submit` now means the work is ready for its review gate, and fixes made in response to that review need no status change. The skill loads when a request names a Mimir id or reads or changes the board, rather than at the start of every session.
- **The skill prefers the MCP tools** (MMR-608). When the host has the Mimir MCP server configured, the skill directs the agent to its tools instead of shell calls, and to the CLI otherwise. It names the machine-local commands that have no tool and stay on the CLI: `bind`, `pair`, `doctor`, `store`, `version`, `skills`, `self-update`, and `mcp`.
