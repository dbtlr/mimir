- **The skill describes Mimir, not a delivery process** (MMR-608). The `mimir` skill states what each record, status, and verb claims and leaves which work to take, how follow-ups are routed, and how a session is organized to the user's and the project's own process. It no longer requires orienting before every request, preferring groomed work, holding one `in_progress` task per session, or filing every deferred follow-up as a task. It keeps what each claim means: `start` before the first edit, `done` only when verified and before the user hears the work is finished, a reservation released when its run is cancelled, `reopen` only to correct a wrong terminal call, a held task's holder making its transitions, the finishing records in the order their data requires, what a Scratchpad and a `groomed` task are for, and that only a board's owners create its tasks. `submit` now means the work is ready for its review gate, and fixes made in response to that review need no status change. The skill loads when a request names a Mimir id or reads or changes the board, rather than at the start of every session.
- **The skill prefers the MCP tools** (MMR-608). When the host has the Mimir MCP server configured, the skill directs the agent to its tools instead of shell calls, and to the CLI otherwise. It names the machine-local commands that have no tool and stay on the CLI: `bind`, `pair`, `doctor`, `store`, `version`, `skills`, `self-update`, and `mcp`.
