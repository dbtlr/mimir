- **Read words after `--` as arguments, and refuse the ones no argument takes** (MMR-746). Mimir now builds on Loom 0.20.0, where words after `--` fill a command's arguments. A title, note, reason, tag, or query that leads with a dash still works, as in `mimir park MMR-3 -- -1 day` or `mimir create task --parent MMR-2 -- --two words`, and now works on `decide`, `confirm`, `overturn`, `decline`, and `create project` too, which refused it before. `mimir bind -- KEY` now binds `KEY`, as `mimir bind KEY` does; it used to ignore the word and print the current binding. A word that no argument takes now fails with exit 2 on every command. Commands that never read words after `--`, such as `get`, `list`, `update`, `seed`, `promote`, and `item check`, used to ignore them and run. The lifecycle verbs and `land` now say `Command "start" accepts 1 argument.` with code `unexpected-argument`, where they said `unexpected argument: <word>` with code `usage`. `item check MMR-3 -- -1` now reads `-1` as the item number and refuses it as not positive. Help lists Loom's `--fields` on every command with `--format`, but Mimir's own `json` and `jsonl` views refuse it with exit 2, and the MCP tools do not take it.
- **Refuse words beside the flag that replaces them** (MMR-746). `create` with a title and words after `--`, `decline` and `item drop` with `--reason` and reason words, `scratch create` with `--title` and title words, `scratch agenda supersede` with `--reason` and reason words, and `scratch agenda complete` with words after the item number each kept one and dropped the other in silence. Each now fails with `unexpected argument: <words>` and exit 2, and writes nothing. These also refuse, with exit 2 and a message that names the conflict, and write nothing: `create project` refuses a name given both as the argument and as `--name`, `triage` refuses a board given both as the argument and as `--scope`, `scratch agenda add` and `complete` refuse `--reason`, which only `supersede` takes, and `scratch checkpoint` refuses inline text beside `--file -`.
- **Refuse `mimir mcp --http`** (MMR-746). Loom 0.20.0 offers MCP over HTTP, with no authentication unless the application adds one. Mimir serves MCP over stdin and stdout only, so `mcp --http` fails with exit 2 before any server starts, and an HTTP request would get 401. Help still lists the option.
- **Known limitation: skills installed by this release cannot be updated by an older one** (MMR-746). Loom 0.20.0 writes the skills installation record in a newer format. After a downgrade to 0.30.x, `mimir skills update` fails until you remove the record it names and run `mimir skills install` again.
