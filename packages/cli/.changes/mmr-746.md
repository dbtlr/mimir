- **Refuse every word after `--` that no argument takes** (MMR-746). Mimir now builds on Loom 0.20.0, where words after `--` fill a command's arguments. A title, note, reason, tag, or query that leads with a dash still works, as in `mimir park MMR-3 -- -1 day` or `mimir create task --parent MMR-2 -- --two words`. A word that no argument takes now fails with exit 2 on every command. Commands that never read words after `--`, such as `get`, `list`, and `update`, used to ignore them, and `create` dropped them when it already had a title. The lifecycle verbs and `land` now say `Command "start" accepts 1 argument.` with code `unexpected-argument`, where they said `unexpected argument: <word>` with code `usage`. `decide`, `confirm`, and `overturn` no longer say to quote the text as one argument. `item check MMR-3 -- -1` now reads `-1` as the item number and refuses it as not positive. Help lists Loom's `--fields` on every command with `--format`, but Mimir's own `json` and `jsonl` views refuse it with exit 2, and the MCP tools do not take it.
