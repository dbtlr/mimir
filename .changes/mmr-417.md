### Added

- **A SQLite local tier, the new default store** (MMR-417). A new install needs
  no `norn` binary and no vault. Mimir keeps work state in one file,
  `store.sqlite`, in the installation's data directory, and creates and
  migrates it forward on open. A database file that holds unrelated tables is
  refused. `[store] backend` now accepts `sqlite` (the default), `postgres`,
  and `norn`, and `mimir doctor` runs one shared SQL check over SQLite and
  Postgres. See `docs/decisions/0032-sqlite-local-tier-shared-sql-store.md`.

### Changed

- **Setup, service install, and store upgrade follow the backend** (MMR-417).
  On sqlite and postgres, `mimir setup` asks only about the background service,
  and `--vault`, `--install-snapshot`, `--snapshot-interval`, and `--upstream`
  are refused. `mimir service install` needs `norn` and a vault only on the
  norn backend. `mimir store upgrade` on sqlite opens the store, which migrates
  it, and reports the versions it moved from and to.
- **An install with no `[store] backend` now opens SQLite, not its Norn vault**
  (MMR-417). To keep the vault, add `backend = "norn"` under `[store]` in the
  config. To move to SQLite, run `mimir store export <file>` while
  `backend = "norn"` is set, remove that line, then run
  `mimir store import <file> --apply`. Back up SQLite with
  `store export`, not by copying the live database file. The norn backend stays
  selectable.
