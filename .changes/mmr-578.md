### Added

- **The Loom CLI reaches a host in remote mode** (MMR-578). When `config.toml` names a host with `[host] url`, the Loom CLI sends every work-state command through `RemoteEngine` to that host's `/trpc`, using the device token from `credentials.toml` beside the config, and opens no store of its own. It refuses with the fix when the config holds both `[host]` and `[store]`, when the credentials are missing, not private to their owner, or recorded for another host, and when the host rejects the token, redirects, answers without a Mimir response, or cannot be reached. `mimir store` and `mimir doctor` refuse in remote mode and point to `mimir-host`. Pairing with a host follows in MMR-579.

### Changed

- **A config that names a host opens no local store** (MMR-578). Each store has one owner ([ADR 0038](docs/decisions/0038-device-pairing-and-the-version-window.md)), so a CLI without remote mode refuses a `config.toml` with a `[host]` section instead of opening a local SQLite store in the host's place.
